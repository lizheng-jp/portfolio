&emsp;&emsp;算是学习Android以来，对Handler的一个总结和整理。


### 一、为什么要用Handler？
&emsp;&emsp;第一次接触到Handler，是因为Android在主线程中无法进行耗时操作，需要通过子线程来完成，而子线程是无法更新UI线程的，这里就需要通过Handler去通知主线程更新。
### 二、什么是Handler？
先来看下源码里的注释是怎么说的。
> ```A Handler allows you to send and process \{@link Message} and Runnable objects associated with a thread’s \{@link MessageQueue}. Each Handler instance is associated with a single thread and that thread’s message queue. When you create a new Handler, it is bound to the thread message queue of the thread that is creating it – from that point on, it will deliver messages and runnables to that message queue and execute them as they come out of the message queue.

&emsp;&emsp;也就是说Handler可以传递Message和Runnable，而且每个Handler的实例都与单独的线程以及它的消息队列相关。当你创建一个Handler对象时，它就被创建它的线程的消息队列绑定。从那一刻起，它就会向消息队列发消息以及执行他们。每个线程只有一个消息队列，可以有多个Handler和Message。
### 三、Handler的作用
> There are two main uses for a Handler: (1) to schedule messages and runnables to be executed as some point in the future; and (2) to enqueue an action to be performed on a different thread than your own.

&emsp;&emsp;两个主要的作用，一个是安排message和runnable在未来的某个时间点执行，另一个是在不同于自己的线程执行一个操作。举个例子，比如你想判断一个连接是否成功，服务器是否给你回调，你需要弹出提示框来告诉用户服务器有没有反应，有一个办法是在连接之前通过Handler进行延时发送无回调的消息，如果服务器有回调了，那就将这个Handler移除（remove）掉。
### 四、Handler的用法
&emsp;&emsp;实例化一个Handler对象。
```Java
Handler handler = new Handler() { 
    @Override            
    public void handleMessage(Message msg) {               
        super.handleMessage(msg);         
    }       
};
```

&emsp;&emsp;在我实际使用中，这样写的更多些。

```Java
 Handler handler = new Handler() {       
        @Override          
        public void handleMessage(Message msg) {           
            super.handleMessage(msg);            
            switch(msg.what){               
                case CONNECT_SUCCESS :                
                    //todo                  
                    break;                  
                case CONNECT_HANGUP;                
                    //todo                  
                    break;        
                default:               
                    break;
            }
        }
    };
```
 
&emsp;&emsp;这样可以在不同的子线程里发送不同的Message，然后通过Handler依次更新UI线程。
那么如何发送Message或者Runnable呢？
有以下几种方法：
- post(Runnable)
- postAtTime(Runnable, long)
- postDelayed(Runnable, long)
- sendEmptyMessage(int)
- sendMessage(Message)
- sendMessageAtTime(Message, long)
- sendMessageDelayed(Message, long)

&emsp;&emsp;这里的Message是可以携带对象的，它用于线程之间交换数据，实际使用中可以这样操作。
```Java
Message msg = new Message();
msg.what = CONNECT_SUCCESS;
msg.obj = "连接成功！";
handler.sendMessageDelayed(msg, 1 * 1000);
```

&emsp;&emsp;延迟1s然后发送包含数据的信息，传递到handler里handlerMessage方法中，handler找到对应的msg.what后做相应的处理。

&emsp;&emsp;大致过程是这样的，通过send或者post将message放入Message Queue(消息队列)中，等待被处理，这时候有一个像水车一样的东西叫Looper，它会无限循环的转，每当发现Message Queue中存在message时，就会将它取出并传递到handleMessage()方法中。
### 五、Handler与内存泄露
&emsp;&emsp;内存泄露大致是因为无法回收垃圾对象，从而使实际可用内存变小，这个以后会详细讲，我们这里只要了解它和handler有什么关系。
  
&emsp;&emsp;原因：当使用内部类来创建Handler时，Handler会持有一个外部类对象Activity的引用，而Handler通常会带有耗时操作，也就是在执行完耗时操作以后才会通过消息机制通知Handler，在这个过程中，如果Activity不再被使用，但Handler又持有Activity的引用，那就会导致Activity无法被回收，最终导致内存泄露。
解决方法：
- 方法一
&emsp;&emsp;在Activity销毁的时候加上这句话
```Java
 handler.removeCallbacksAndMessages(null);
```
 
&emsp;&emsp;将消息对象从消息队列中移除。
- 方法二
使用静态类配合弱引用（WeakReference）
```Java
static class UIHandler extends Handler {
        WeakReference<Activity> mActivityReference;     
        
        UIHandler(Activity activity) {  
            mActivityReference = new WeakReference<Activity>（activity）; 
        }   
        
        @override   
        public void handleMessage(Message msg) {    
            final Activity activity = mActivityReference.get(); 
            if (activity != null) {         
                //todo      
            }   
        }
    }
```

&emsp;&emsp;当然如果handler对象还是在Message队列里，还是要将它移除的，也就是使用方法一。
### 六、Handler的不足之处
&emsp;&emsp;在实际开发中，如果大量使用Handler会导致代码可读性很差，而且让人有种摸不着头脑的感觉，会随着程序逻辑变得越来越复杂，听说RxJava的优势是程序简洁性，让逻辑没那么复杂，所以我会抽空研究一下RxJava。
