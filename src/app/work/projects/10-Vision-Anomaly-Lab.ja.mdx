## 作った理由

[カメラモジュールの外観検査](/work/2-STB)では、製品画像の位置・背景・照明がばらつき、背景で誤検出が発生していました。SAM で部品を背景から切り出してから PatchCore で採点すると、精度が上がりました。ただしデータは社外秘のため、結果を外部に示せませんでした。

Vision では、この知見を公開データセット [VisA](https://github.com/amazon-science/spot-diff) で再現しています。**背景が誤検出の原因になる場面で、SAM による背景分離は異常検知を改善するのか、それはどんな条件で成り立つのか**を確かめました。再現の信頼性は評価方法で決まるため、元の取り組みで後から気づいた問題（画像単位のランダム分割、テストデータで調整したしきい値）が起きない評価手順にしています。

**公開デモ：** [vision.lizheng.cc](https://vision.lizheng.cc/?lang=ja)（日本語 / English） · **ソースコード：** [github.com/lizheng-jp/patchcore-visa](https://github.com/lizheng-jp/patchcore-visa)

## 評価手順

- 公式の正常画像のみの学習データで学習します。
- 公式テストセットをカテゴリごと・ラベルごとに検証用とテスト用に分割します（seed 固定）。
- 判定しきい値は検証データだけで選び（F1 最大または Youden J）、テストには一度だけ適用します。
- しきい値に依存しない画像 AUROC（論文と比較可能）と、しきい値適用後の再現率・特異度・F1 を報告します。ラベル 1 は常に異常を表します。

## 結果（12 カテゴリ、seed 1 つ）

| 指標 | 値 |
|---|---|
| 画像 AUROC | **0.902** |
| 画素 AUROC | **0.981** |
| 事後的な SAM マスク適用時の画像 AUROC | 0.905 → **0.931** |
| 1 枚あたりの推論時間 | GPU 7–15 ms、CPU 1.1–2.2 秒 |

単一物体のカテゴリは画像 AUROC 0.97–0.99 に達します。弱点は複数物体のカテゴリ（capsules、macaroni）です。画素 AUROC は高く欠陥の位置は特定できていますが、画像スコアが主に背景にある正常領域の高スコアに引きずられます。

## 背景が誤検出の原因になる場面で再現、そして効かない条件

<img src="/images/projects/vision/sam_tradeoff.png" alt="カテゴリごとの SAM マスクによる改善量と欠陥カバー率" style={{ width: '100%', height: 'auto' }} />

工場の状況に対応するのは Macaroni です。模様のあるマットの上に小さな物体が並び、誤検出の多くは背景で起きています。ここでは SAM の前景内だけで採点すると、画像 AUROC が macaroni2 で +0.16、macaroni1 で +0.13 改善しました。全 12 カテゴリで確認すると、成り立たない条件も分かりました。SAM が欠陥の一部を切り落としたり、接触した物体を分割したりした fryum と capsules では、約 0.03 低下しました。欠陥カバー率だけでは結果を予測できないため、導入前に製品ごとのマスク品質の確認が必要です。

公開デモのモデルでも、訪問者と同じ使い方で再検証しました。検証・テストの全 200 枚で各パスタに EfficientSAM の提示点を 1 つずつ置き、しきい値はそれぞれ検証データで選びました。

| Macaroni2・未使用テスト | 全画像 | SAM 前景 |
|---|---|---|
| 画像 AUROC | 0.634 | **0.797** |
| 誤検出（正常 50 枚中） | 38 | **23** |
| 見逃し（異常 50 枚中） | **6** | 9 |

<img src="/images/projects/vision/macaroni2-false-alarm-removed.jpg" alt="誤検出の解消：最高スコアはパスタではなくマット上にあった" style={{ width: '100%', height: 'auto' }} />

*誤検出の解消：最高スコアの画素（白丸）はマット上の小さな点でした。マスク内ではしきい値を下回ります。*

<img src="/images/projects/vision/macaroni2-counterexample.jpg" alt="反例：背景が原因で異常と判定されていた異常画像" style={{ width: '100%', height: 'auto' }} />

*反例：この異常画像は、マスク前は背景が原因で異常と判定されていました。マスクは欠陥全体（赤線）を残していますが、欠陥だけのスコアはしきい値未満です。見逃しが 6 件から 9 件に増えたのは、このような画像のためです。*

## デモの実装

- 実際の PatchCore（Wide ResNet-50、正常画像 200 枚の特徴庫）と EfficientSAM を CPU で動かす Python 推論サーバー。一度に読み込むモデルは 1 つです。
- ヒートマップの色範囲はカテゴリごとに固定し、画像間で色を比較できるようにしました。すべての未使用テスト画像のスコアを、検証データで選んだしきい値とともに表示します。
- 同梱サンプルは最も簡単な画像ではなく、正しく判定された典型的なテスト画像（20 / 50 / 80 パーセンタイル）です。誤判定はスコアのグラフにすべて表示しています。
- モデルを読み取り専用でマウントし、メモリと CPU を制限した Docker イメージを、AWS Lightsail 上の Caddy の背後で運用しています。アップロード画像はメモリ内で処理し、保存しません。

## 限界と今後

結果は seed 1 つのみで、±0.02 程度の差は過大に解釈できません。seed 1–2、学習前の入力マスク、小さい backbone、coreset 比率、512 px 解像度の実験はスクリプト化済みですが、まだ実行していません。
