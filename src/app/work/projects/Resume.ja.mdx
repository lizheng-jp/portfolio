- **[開発者生産性評価システム](/work/7-DeveloperEvalutionSystem/ja)**: Spring Boot、Next.js、PostgreSQL、GitLab API を用いて、Issue・Merge Request・Commit・レビュー・満足度アンケートから SPACE ベースの生産性指標を算出する社内 PoC を 0 から構築。プロジェクト単位・メンバー単位のダッシュボードを実装。Docker Compose、Jenkins デプロイ、Actuator・Micrometer・Prometheus・Grafana による監視を構築。
- **[LLM による MR 分析](/work/8-AI-MR-Analysis-Pipeline/ja)**: Gemini API を構造化 JSON 出力、High/Middle/Low の段階評価、フォールバック付きで統合。非同期 Batch API と結果の永続化、プロンプトキャッシュの共有、標準 API へのフォールバックを軸にパイプラインを再設計し、テストで発生していた同期 HTTP タイムアウトを解消。評価対象の処理量で推定 API コストを約 50% 削減。プロンプト改善により、人手で確認したサンプルで人間のレビューとの一致度が約 30% 向上。

- **[QR コード勤怠アプリ](/work/4-Flutter-QRCode)**: 従業員 2 万人以上の組織向けに Flutter のクロスプラットフォームアプリを構築。プロキシ環境下の WebView 認証、クライアント証明書処理、Firebase Cloud Messaging によるバックグラウンドでの QR コード更新を実装。

## 📂 個人プロジェクト

### [Dev Productivity Signals](/work/9-Dev-Productivity-Signals/ja) _(Spring Boot + Next.js + Python + Gemini + Qdrant)_
- 回数制限付きの API Tool で開発指標を取得し、プロジェクト・ブランチ単位の Qdrant ベクトルインデックスから GitHub の PR・Issue の議論を検索（RAG）して出典付きで回答する LLM Agent「Signals Agent」を Gemini の Function Calling で構築。
- 1 回の質問を Tool 呼び出し 5 回・モデル応答 6 回・240 秒に制限し、根拠が弱い場合や不完全な場合は原因を断定せずその旨を提示。
- Prometheus・Grafana による P95 応答時間と失敗率の監視、変更のない Embedding を再利用する差分インデックス更新を実装。Docker Compose と GitHub Actions で AWS Lightsail にデプロイ。
