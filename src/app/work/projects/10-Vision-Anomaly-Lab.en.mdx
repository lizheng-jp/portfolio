## Why I built it

My [camera module inspection work](/work/2-STB) taught me that evaluation design matters as much as the model: random image-level splits and thresholds tuned on the test set made early results look better than they were. Vision rebuilds the same idea (PatchCore anomaly scoring with optional SAM foreground masking) on the public [VisA](https://github.com/amazon-science/spot-diff) dataset, from scratch, with those mistakes designed out.

**Live demo:** [vision.lizheng.cc](https://vision.lizheng.cc/) (English / 日本語) · **Source:** [github.com/lizheng-jp/patchcore-visa](https://github.com/lizheng-jp/patchcore-visa)

## Evaluation protocol

- Train on the official normal-only training split.
- Split the official test set per category and per label into validation and test halves (seeded).
- Select the decision threshold on validation only (max F1 or Youden J), then apply it once to test.
- Report threshold-free image AUROC (comparable with papers) plus thresholded recall, specificity and F1. Label 1 always means anomalous.

## Results (12 categories, one seed)

| Metric | Value |
|---|---|
| Image AUROC | **0.902** |
| Pixel AUROC | **0.981** |
| Image AUROC with post-hoc SAM masking | 0.905 → **0.931** |
| Inference per image | GPU 7–15 ms; CPU 1.1–2.2 s |

Single-object categories reach 0.97–0.99 image AUROC. Multi-instance categories (capsules, macaroni) are the weak spot: their pixel AUROC stays high, so defects are localized, but the image score is dominated by high-scoring normal regions, mostly in the background.

## Does SAM masking help? Sometimes, and not for free

<img src="/images/projects/vision/sam_tradeoff.png" alt="SAM masking gain versus defect coverage per category" style={{ width: '100%', height: 'auto' }} />

Scoring only inside the SAM foreground raised image AUROC by +0.16 on macaroni2 and +0.13 on macaroni1, but lowered it by about 0.03 on fryum and capsules, where SAM cut off parts of defects or split touching objects. Defect coverage alone does not predict the outcome, so mask QA has to be checked per category before shipping masking.

On the live demo model I repeated the test the way a visitor uses it: one EfficientSAM point per pasta piece on all 200 validation and test images, with each threshold chosen on validation.

| Macaroni2, held-out test | Full image | SAM foreground |
|---|---|---|
| Image AUROC | 0.634 | **0.797** |
| False alarms (of 50 normal) | 38 | **23** |
| Missed defects (of 50 anomalous) | **6** | 9 |

## Demo engineering

- Python inference server with real PatchCore (Wide ResNet-50, 200-image memory banks) and EfficientSAM, CPU only, one model loaded at a time.
- Heatmaps use a fixed colour range per category, so colours are comparable across images. A score chart shows every held-out test image against the validation-selected threshold.
- Bundled samples are typical correctly classified test images (20th / 50th / 80th percentile), not the easiest ones; the chart still shows every error.
- Docker image with read-only model mounts, memory and CPU limits, behind Caddy on AWS Lightsail. Uploaded images are processed in memory and never stored.

## Limits and next steps

Results come from one seed; differences of about ±0.02 should not be over-read. Seeds 1–2, input-level masking before training, a smaller backbone, coreset ratio and 512 px resolution are scripted but not yet run.

## Tech stack

PyTorch, anomalib (PatchCore), Wide ResNet-50, SAM / EfficientSAM, OpenCV, scikit-learn, NumPy, Python HTTP server, Docker, Caddy, AWS Lightsail
