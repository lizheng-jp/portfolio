## Overview

At a manufacturing company, I built a visual inspection pipeline that flags anomalous camera module components from production images. The work combined image segmentation, unsupervised anomaly detection, and supervised classification experiments.

This is an anonymized case study. Product images, data, model weights, and evaluation numbers are intentionally omitted because they belong to the company.

## Pipeline

1. **Region extraction**: Production images varied in position, background, and white balance. I used SAM / EfficientSAM with OpenCV post-processing to isolate the component and mask out the background before scoring.
2. **Anomaly scoring**: PatchCore with a Wide ResNet backbone builds a coreset memory bank of patch features from normal images only; a test image is scored by its nearest-neighbor patch distance, producing both an image score and a heatmap. FAISS handles the nearest-neighbor search.
3. **Classification experiments**: I also trained ResNet-based classifiers, including a variant that combined image features with device metadata, to compare supervised and unsupervised approaches.
4. **Experiment tracking**: MLflow recorded parameters, metrics, and misclassified samples.

## Data scale

Around 6,000 production images from 14 inspection devices across two collection periods, labeled good or defective.

## What re-examining the evaluation taught me

When I later reviewed the experiments, I found that the early evaluation was more optimistic than it should have been:

- **Random image-level splits** put images from the same production lot and device into both training and test sets, so the test set did not represent new production data.
- **The decision threshold was chosen on the test set itself**, which inflates accuracy and F1.
- **Device metadata as a model input** can let a classifier learn device-specific shortcuts instead of defect appearance.

Re-evaluating with lot-disjoint splits, a threshold selected only on validation data, and a later production batch as the test set gave much weaker results. The main lesson: in manufacturing inspection, evaluation design — how data is split across lots, devices, and time — matters as much as model choice.

I am applying this lesson in a public reimplementation of the pipeline on open industrial anomaly detection datasets.

## Tech stack

PyTorch, SAM / EfficientSAM, PatchCore, Wide ResNet, ResNet, FAISS, OpenCV, NumPy, Pandas, MLflow
